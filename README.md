# The Borrowed Pantry

**Same soul, different store.**

An agentic cooking assistant for African students living abroad. Tell it what you want to
eat, and it works out what you can actually buy near you, what to substitute for the things
you can't find, and whether it fits your budget — then remembers everything for next time.

Built for the CockroachDB × AWS Agentic Memory Hackathon.

---

## The problem

Food has a way of making a place feel like home—until you're far from it.

When I moved from Ghana, I craved garden egg stew, only to discover that the ingredients I had always taken for granted simply weren't available. There were no garden eggs, no kpakpo shito, no dried smoked fish, no palm nut cream.

Like many people living away from home, I learned to substitute. Italian eggplant instead of garden eggs. Habanero instead of kpakpo shito. Some substitutions worked surprisingly well. Others changed the dish completely. Nobody tells you that vegetable oil will technically cook your stew, but it strips away the rich color and flavor that make it feel like home.

And this isn't unique to Ghanaian food. Whether it's Mexican chiles, Korean perilla leaves, Japanese shiso, or Indian curry leaves, people everywhere face the same question:
"What can I use instead?"

The answers exist—but they're scattered across family phone calls, WhatsApp group chats, Reddit threads, and years of trial and error. That knowledge is difficult to search, easy to lose, and impossible for AI to reason about.

Borrowed Pantry transforms that collective knowledge into structured, searchable data that both people and AI agents can use—helping anyone find substitutions that preserve the flavor, texture, and identity of a dish, no matter where they are.

## What it does

The app walks you through one guided flow:

1. **What are you planning to eat?** — Name any African dish. If it isn't in the database
   yet, the agent generates the full recipe, ingredient list, substitution knowledge, and
   store availability on the spot, then saves it permanently.
2. **Where are you shopping?** — Stores sorted by real distance from your device location,
   tagged with whether they deliver via Uber Eats or DoorDash.
3. **What do you already have?** — Check off what's in your kitchen, remove what you don't
   want, add extras, set your budget. Anything you already own is excluded from pricing
   entirely, not just noted.
4. **Your plan** — An itemised basket with a deterministic total. Every substitution comes
   with a plain-language reason: what changes about the dish, how to prepare it differently,
   and when it's honestly a bad idea. If an essential ingredient has no good substitute, it
   says so and points you to a store that stocks the real thing.
5. **Shopping list** — Tick items off as you find them in the aisle.
6. **Cooking steps** — Written method, plus a video link.
7. **Done cooking** — Saved to your history with the exact basket you bought, so you can
   pull the whole thing up again months later.

Alongside the flow: a **Community** page where anyone can share a substitution that worked
for them, and those tips feed directly back into the agent's planning for everyone else.

## Why memory is the point

An agent that forgets is a search box. This one is built so that everything it learns
persists in CockroachDB and changes what it does next:

**Personal memory.** After every conversation, the agent extracts durable facts — your
budget, dietary restrictions, substitutes you've approved, stores you prefer — and stores
them as structured rows. Close the app, come back next week, ask "what should I cook on a
budget," and it already knows the answer to "what budget?"

**Allergy memory.** Dietary restrictions saved once at signup permanently change how baskets
are built. If you're allergic to shellfish, crab is force-excluded from every recipe that
contains it and the agent hunts for a substitute — even at a store that has crab in stock.

**Cooking memory.** Every finished dish is saved with the exact basket you bought and what
it cost. Tap it months later and the whole plan comes back.

**Community memory.** This is the strongest case. A tip shared by one person in Jacksonville
becomes knowledge the agent offers to a different person in a different city, months later.
Miso paste instead of locust beans, because both are fermented soybean products — that's
real culinary knowledge, contributed by a human, stored in CockroachDB, and surfaced by the
agent inside someone else's shopping plan with attribution.

**Learned recipes.** A dish generated for one user is permanently available to everyone
after. The catalogue grows on its own.

## CockroachDB tools used

### Distributed Vector Indexing

Every ingredient and recipe carries a `VECTOR(1024)` embedding generated by Amazon Titan
Text Embeddings V2, with vector indexes on both tables. This powers semantic search over the
ingredient catalogue — searching "something like garden eggs" returns thai eggplant and
italian eggplant without any keyword overlap, and "a spicy hot pepper" returns all three
pepper varieties without the word "pepper" needing to match anything.

Because vectors live in the same database as the operational data, there's no separate
vector store to keep in sync, and a semantic lookup can join directly against live store
inventory in one query.

### CockroachDB as the agentic memory layer

The entire memory system is CockroachDB, across thirteen tables: conversation transcripts,
extracted user facts, cooking history with saved baskets, community-contributed
substitutions, generated recipes, and the ingredient/substitution knowledge graph. Nothing
about the agent's memory lives in application state — restart the process, and it picks up
exactly where it was.

### Cloud Managed MCP Server

Connected via OAuth to Claude Code during development and used for live schema inspection
and debugging against the running cluster.

A concrete example of it earning its place: asked to describe the schema for this README, it
reported seven vector indexes on `ingredients` and seven on `recipes` instead of one each.
Repeated runs of the migration script had been silently stacking up duplicate unnamed indexes
across development. That bug was completely invisible from the application side — every query
worked fine — and would have shipped unnoticed. Twelve redundant indexes were dropped, and
the migration was changed to create them by explicit name so it can't recur.

## AWS services used

### Amazon Bedrock

Three distinct jobs, all through Bedrock:

- **Claude Sonnet 4.6** as the agent's reasoning engine — building shopping plans, explaining
  substitution tradeoffs, writing cooking steps, and answering follow-up questions.
- **Claude Sonnet 4.6** as a structured-data generator — when a user names a dish the
  database doesn't know, it returns a full JSON recipe (ingredients, quantities, store
  availability, price estimates, and substitutions with reasons), which is parsed and
  persisted to CockroachDB.
- **Amazon Titan Text Embeddings V2** for the 1024-dimension vectors stored in
  CockroachDB's vector columns.

A lightweight routing call to Claude also decides, per message, whether an incoming chat
message needs a full recipe-and-store data fetch or can be answered conversationally.

## Architecture

```
React (Vite) frontend
        |
        v
FastAPI backend  ──────────────►  Amazon Bedrock
        |                          ├── Claude Sonnet 4.6 (reasoning, generation, routing)
        |                          └── Titan Embeddings V2 (1024-dim vectors)
        v
CockroachDB Cloud (AWS us-east-1)
  ├── Vector indexes on ingredients + recipes  (semantic search)
  ├── Agent memory: conversations, messages, user_facts
  ├── Knowledge: substitutions, substitution_reviews (community)
  ├── Catalogue: recipes, ingredients, recipe_ingredients
  ├── Commerce: stores, store_inventory
  └── History: cooked_history, user_favorite_recipes
```

## Data model

Thirteen tables. Schema below was pulled from the live cluster via the CockroachDB MCP
Server.

**Catalogue**

- `recipes` — name (unique), cuisine, description, video_url, est_time_minutes,
  `embedding VECTOR(1024)`, `is_generated`
- `ingredients` — name (unique), category, origin_note, `embedding VECTOR(1024)`
- `recipe_ingredients` — recipe_id + ingredient_id (composite PK), quantity, is_essential
- `stores` — name (unique), chain, address, lat, lng, store_type, on_ubereats, on_doordash
- `store_inventory` — store_id + ingredient_id (composite PK), price, unit, in_stock,
  is_estimated

**Knowledge**

- `substitutions` — original_id + substitute_id (composite PK, both → ingredients), notes
- `substitution_reviews` — community tips: original_id, substitute_name, notes, user_id,
  recipe_id

**Memory**

- `users` — email (unique), display_name, default_budget, dietary_restrictions
- `conversations` — user_id, title, created_at
- `messages` — conversation_id, role, content, created_at
- `user_facts` — user_id, fact_type, content, source_conversation
- `cooked_history` — user_id, recipe_id, store_name, `basket JSONB`, total, cooked_at
- `user_favorite_recipes` — user_id + recipe_id (composite PK)

## Running it locally

### Prerequisites

- Python 3.12+
- Node 18+
- A CockroachDB Cloud cluster (the free Basic tier is enough)
- An AWS account with Bedrock access to Claude Sonnet and Titan Text Embeddings V2

### Backend

```bash
git clone https://github.com/efyastar/borrowed-pantry.git
cd borrowed-pantry

python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Create a `.env` file in the project root:

```
DATABASE_URL=postgresql://<user>:<password>@<host>:26257/meals_agent?sslmode=verify-full
```

Download your cluster's CA certificate (the exact command is in the CockroachDB Cloud
console under Connect → Download CA Cert):

```bash
curl --create-dirs -o $HOME/.postgresql/root.crt -O <your-cluster-cert-url>
```

Configure AWS credentials for Bedrock:

```bash
aws configure          # region: us-east-1
```

Create the schema and load the seed data:

```bash
python3 db.py          # creates 13 tables + vector indexes
python3 seed.py        # loads starter recipes, ingredients, stores, substitutions
python3 embeddings.py  # generates embeddings via Titan
```

Run the API:

```bash
uvicorn api:app --reload --port 8000
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`.

To test from a phone on the same network, run the backend with `--host 0.0.0.0`, change
`API_BASE` in `frontend/src/api.js` to your machine's LAN IP, and start Vite with
`npm run dev -- --host`.

## Honest notes on the data

Worth being explicit, since a judge will reasonably ask:

**Store inventory and prices are representative, not live.** Neither Uber Eats nor DoorDash
exposes a public API for store-level grocery inventory, and most grocery chains don't either.
The three seeded stores use realistic Jacksonville locations and plausible prices; generated
recipes have their availability and pricing estimated by Claude and flagged in the database
with `is_estimated`. Production would integrate real retailer APIs. The agent's reasoning,
substitution logic, and budget arithmetic are all real and would work unchanged against live
data.

**Two dishes are hand-verified.** Garden Egg Stew and Palmnut Soup, along with eight
substitution reasons, were written and checked by someone who cooks them. Everything else is
generated. Hand-curated substitutions always take precedence over generated ones when both
exist for the same ingredient.

**Budget arithmetic is deterministic, not model-generated.** Totals, budget fitting, and
what-to-cut decisions are computed in Python and handed to Claude as fixed facts it is
instructed not to recalculate. This was a deliberate fix — earlier versions had the model
doing arithmetic in prose, and it drifted.

## Known limitations

- The agent re-derives context per message rather than holding a locked plan object across
  turns, so a multi-turn conversation can restate a budget concern in slightly different
  terms.
- Allergy detection maps a fixed set of restriction labels to ingredient names. It handles
  the common cases but is not exhaustive.
- Generated recipes aren't reviewed by a human before being saved.
